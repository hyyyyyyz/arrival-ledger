# 人员责任与人工收货纠正

本系统要求公司内每位操作人员使用自己的账号登录。照片拍摄、运单号修正、订单人工收货与账号管理均记录
实际操作人和服务器时间；停用账号不会删除历史责任记录。

## 1. 收货状态的两层事实

系统把“照片证据”和“当前业务结论”分开保存：

- **照片证据状态**由已保存的收货照片、运单号和订单包裹关系计算，人工操作不会删除或篡改照片；
- **当前有效状态**默认等于照片证据状态，也可以由人员人工改为“已收货”或“未收货”；
- 取消或退款订单固定为“无需收货”，不能人工改成其他状态；
- 订单列表会明确显示“照片凭证”或“人工确认/人工撤销”，并显示责任人和时间。

人工纠正采用乐观并发控制。同一订单被两个人同时打开时，后提交者不会覆盖先提交者，而会收到冲突提示并刷新
最新状态。每次操作带唯一事件编号；网络超时后重试同一操作不会生成重复审计事件。
同一事件编号只接受完全相同的请求；若该记录后来又被其他人修改，旧请求重放会返回冲突，而不会把当前最新状态
伪装成旧操作的成功结果。

## 2. 日常使用

### 管理员添加同事

1. 使用管理员账号登录；
2. 在手机底部导航进入“人员”；
3. 点击“新增人员”，填写唯一登录账号、责任人姓名、初始密码和角色；
4. 普通同事选择“收货员”，只有需要管理其他账号的人才选择“管理员”；
5. 员工离职或暂时停用时，在人员列表中停用账号。停用会立即撤销该人员的现有登录会话。

系统不开放公开注册，也不会在人员列表回显密码。每个人必须使用自己的账号，禁止多人共用管理员账号，否则无法
准确追责。

### 员工修改自己的密码

登录后点击页面右上角“修改密码”，输入当前密码、新密码和确认新密码即可。新密码至少 12 个字符，并包含
小写字母、大写字母、数字、符号中的至少 3 类。修改成功后当前设备保持登录，其他设备上的该账号会被要求重新登录。

### 人工纠正订单

1. 在“订单”页找到目标订单；
2. 点击“人工标记已收货”或“人工撤销收货”；
3. 阅读确认框并确认；
4. 卡片立即显示新的有效状态、操作人和服务器时间。

人工撤销只改变订单当前结论，原有照片仍保留。若提示“订单状态已被其他人修改”，刷新后重新核对，不要反复点击。

### 运单号纠错

在“记录”页编辑运单号。保存成功后显示最近修改人和时间；若其他人已经修改，系统返回冲突并要求重新加载，避免
照片被静默改绑到错误订单。

照片责任人始终是最初上传照片的账号；后来修正运单号的人员单独显示为“最近修改人”，不会冒充拍摄人。

## 3. 角色权限

| 功能 | 收货员 | 管理员 |
|---|---:|---:|
| 拍照收货、查看订单与记录 | 是 | 是 |
| 人工确认/撤销订单收货 | 是 | 是 |
| 修正运单号 | 是 | 是 |
| 新增、停用、启用人员 | 否 | 是 |
| 查看账号管理审计 | 否 | 是 |

管理员不能停用自己，也不能停用最后一个有效管理员。账号停用后，历史照片、订单纠正与账号管理审计仍保留。

## 4. API 契约

- `PATCH /api/orders/{order_id}/arrival-status`：人工设置 `PENDING` / `RECEIVED`，要求
  `expected_revision` 与稳定的 `client_event_id`；
- `GET /api/orders/{order_id}/arrival-history`：读取订单人工纠正历史；
- `PATCH /api/receipts/{receipt_id}/tracking`：修正运单号，要求当前预期值与稳定事件编号；
- `GET /api/users`、`POST /api/users`、`PATCH /api/users/{id}`：管理员人员管理；
- `POST /api/auth/change-password`：当前登录用户用原密码修改自己的密码；
- `GET /api/users/audit-events`：管理员查询人员创建、停用与启用审计。

所有责任时间均以服务器记录为准，不信任客户端自行提交的姓名或时间。
