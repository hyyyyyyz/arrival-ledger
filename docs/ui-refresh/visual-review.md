# GUI 视觉迭代记录

本记录遵循根目录 [`DESIGN.md`](../../DESIGN.md) 和 OpenDesign critique 的证据化原则。每版必须使用相同真实数据与视口，分数不能仅凭主观印象上调。

## 固定验收矩阵

| 视口 | 用途 |
| --- | --- |
| 320 × 720 | 最窄支持手机与横向溢出检查 |
| 360 × 800 | 常见 Android 手机 |
| 390 × 844 | 主要移动视觉评分 |
| 430 × 932 | 大屏手机 |
| 1440 × 900 | 桌面自适应，不是主要操作端 |

功能硬门槛：拍照入口可用、三页导航可用、订单可搜索/分页、记录可刷新/修正单号、触控目标 ≥44px、状态不只依赖颜色、320px 无横向滚动。

### V0 保留

- 拍照同时保存本机并识别单号的离线优先流程。
- 收货状态使用文字、图标和颜色共同表达。
- 三个稳定的主入口，不扩张导航层级。

### V0 优先修正

1. 把相机主操作移到收货页首屏，统计降为紧凑摘要。
2. 统一语义令牌与 SVG 图标，移除 Unicode 图标依赖。
3. 订单改为更紧凑的折叠摘要，并增加收货状态筛选。
4. 记录改为时间流式紧凑行。
5. ≥1024px 切换真正的桌面工作台布局。

### 最终生产验收

- 320 × 720：订单卡宽 296px，无横向滚动，最小触控目标 44px。
- 360 × 800、390 × 844、430 × 932：页面宽度均与视口一致；搜索、平台筛选、收货状态筛选和底栏导航可用。
- 1440 × 900：切换为 224px 固定侧栏和三列订单，不再是放大的手机画布。
- 状态筛选：`未收货` 返回 168 条；`已收货` 在当前 0 照片数据下正确显示空态；切回 `全部` 恢复 184 条采购订单。
- 记录空态：“去拍摄包裹”可见且可返回收货拍摄页。
- 生产健康检查：`/api/health` 返回数据库和媒体存储均正常。

### 最终评审结论

- P0：无。
- P1：无发布阻断。320px 首屏仍只完整显示约两张订单摘要，属于后续密度优化项。
- P2：可继续弱化订单卡内部横线；有真实到货照片后补齐“待确认”和“已收货”生产三态截图。
- 发布结论：可交付、可部署，后续迭代不影响当前收货主流程。
